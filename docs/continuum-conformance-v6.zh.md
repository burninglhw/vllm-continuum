## 4. 本次修正的具体含义

### 4.1 三级冷启动

`S` 是已经实际返回的所有工具调用历史，不是程序数量，也不是离线数据集条数。顺序为：

1. `|S| <= 100`：平均1秒的指数分布先验，`eta=1`。
2. `|S| > 100` 且 `|S[f]| <= 100`：全局历史经验CDF，使用经验eta。
3. `|S[f]| > 100`：单工具历史经验CDF，使用经验eta。

例如已经见过101次快速工具，但从未见过一个新工具，新工具也应该使用全局历史，而不是无条件TTL=0。冷启动本身也不意味着一定pin：重建收益太小时，论文目标的最优TTL仍可能为0。

指数先验下令 `mu=1秒`、`B=T+PrefillReload(r)`，式(2)变成：

```text
U(tau) = (1-exp(-tau/mu))*B - tau
U'(tau) = (B/mu)*exp(-tau/mu) - 1

B <= mu: tau*=0
B >  mu: tau*=mu*ln(B/mu)
```

在无队列样本且重建成本为3秒时，旧代码给0，新目标给约1.099秒。这个例子只解释策略分歧，不是对H200模型实际重建时间的断言。

**未消除的文字歧义：**v6将它称为“fixed TTL threshold T_default”，但没有给出统一数值、代表性上下文或该阈值的刷新时机。当前实现按同一式(2)，使用本请求的实测重建成本和当时T求解析最优值。如果作者实际先用代表请求标定一个全局常数，必须由其代码/配置确认，不能擅自把当前推导说成已证明与未公开代码逐行一致。

日志新增 `estimation_source`、`cdf_samples`、`total_tool_samples`、`empirical_eta`、`cold_start_threshold`。其中 `eta` 是本次真正参与计算的值；冷启动是1，不能拿它误当历史相关系数。

### 4.2 抢占优先级

旧代码可以让一个有pin的返回请求排在一个被抢占请求前面，即使后者按v6应该先恢复。现排序分为三组：

```text
0: PREEMPTED
1: 非PREEMPTED，且同程序仍有pin
2: 非PREEMPTED，且同程序无pin
```

每组再按程序首次到达时间升序。请求本轮的到达时间仅用于平局。单纯把被抢占请求`appendleft`不够，因为`peek_request`会重新按键搜索整个队列。

已到期但其返回请求仍在等待队列的pin仍按Algorithm 1保留，避免把§4.3“TTL内优先”的简短说明孤立理解为立刻丢弃这类pin。

### 4.3 到期边界

Algorithm 1 写的是严格 `current_time > P[id]`。本次把`>=`改为`>`，增加“恰好等于截止时间”和“超过截止时间”的两个检查。实际浮点时间相等很少见，但严格对照原文时不应忽略。

## 6. 不能伪装成“原文已规定”的事项

1. **eta如何取样。** 原文定义`-Corr(k,N-k)`，未给出如何跨程序/时间采样k、是否按程序等权、用多少已完成程序及零方差处理。当前每个已完成N轮程序贡献`k=1..N-1`，保留最近256个程序，相关系数无定义时为0。这些选择已公开写在代码中，但没有作者来源证明。
2. **T的窗口与evicted的口径。** 原文说滑动平均，未给窗口长度，也未明确将撤销pin、真正物理覆盖、运行抢占是否统一计入。当前最近256个等待片段，撤销保护/TTL零/运行抢占都会建立相应等待记录。还可能出现unpin后KV未覆盖、后续仍APC命中的情况。不能把“unpin”和“物理缺失”混为一谈。
3. **运行队列竞争与死锁触发范围。** 无进展时的pin牺牲顺序明确；但仍有请求推进时要不要主动unpin、运行请求选择牺牲者的精确顺序、token预算与异步加载如何交互并没有完整伪代码。当前保留原有适配：running缺块先unpin，再按程序年龄抢占；waiting缺块且本tick未安排token才进行死锁unpin。没有把这些未写清的部分当成已认证一致。
4. **工具协议。** 主文§5.1和附录A的mini-SWE示例按单个bash块首词识别；附录B又讨论按`&&/||`拆分子命令。当前采用主文/代码示例的首词约定，组合命令仍是一次整体等待。此外支持单JSON调用和mini-SWE终止标记；并行工具、通用模型function-string、格式错误后的恢复未做通用支持。解析不到工具暂视为程序结束，可能切分真实任务的统计片段。
5. **截止时间起点与延迟释放。** 当前以请求完成时刻加TTL构造deadline，延迟释放回调只取剩余TTL，不重新计时。主文以`current_timestamp+TTL`概括pin操作，但未给异步offload回调的精细时序。
6. **标定及offload。** CPU测试不能验证真实reload、模型数值正确性和共享GPU干扰。现有profile还需在获准的独占/受控GPU条件下重标定；不能直接把H200曲线当作H100曲线使用。
